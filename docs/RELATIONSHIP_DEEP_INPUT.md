# 선택형 심화 입력 (Optional Deep Input)

> 260915 UT P1-1. 구현 위치: [`src/data/relationshipDeepInput.ts`](../src/data/relationshipDeepInput.ts) ·
> [`src/app/profile/deep/`](../src/app/profile/deep/)

---

## 1. 왜 만들었나

UT 신호는 '입력이 많다'가 아니라 그 반대였다.

```
"질문이 너무 얕았음. 이걸로 뭘 알겠어?"
"세부 질문이 부족했던 것 같다"
"질문이 벌써 끝났어?"
```

원인을 넷으로 나눠보면:

| | 진단 |
|---|---|
| A. 질문 수 부족 | **아님.** 기본 흐름은 7화면이고, 이전 UT에서는 오히려 길다고 했다 |
| B. 질문 해상도 부족 | **맞다.** `연락이 얼마나 중요해? 1~5`는 숫자 하나를 얻고 조건을 하나도 모른다 |
| C. 답변 방식이 단순 | **맞다.** 척도와 3지선다뿐이라 '언제 그런가'를 말할 자리가 없다 |
| D. 결과가 근거를 연결 못함 | 부분적. Premium은 이미 연결하지만, 연결할 재료 자체가 얕다 |

그래서 **질문 개수를 늘리지 않고 해상도를 올린다.**

---

## 2. 기본 질문 vs 심화 질문

| | 기본 | 심화 |
|---|---|---|
| 언제 | 모든 사용자 | `+ 더 자세히 알려주기`를 누른 사용자 |
| 어디 | S10~S13 · S15~S17 | S14b `/profile/deep` |
| 개수 | 4 + 3 | 최대 **2** (`MAX_DEEP_INPUTS`) |
| 묻는 것 | **무엇이** 중요한가 | **어떤 조건에서** 그런가 |
| 예 | `연락이 얼마나 중요해? 1~5` | `답장이 늦어질 때, 가장 먼저 신경 쓰이는 건?` |
| 답 형태 | 척도 · 선택 | 선택(+ `잘 모르겠어`) |
| 점수 반영 | 있음(동기화율) | **없음** |

## 3. Trigger — 어떤 질문을 보여주나

`selectDeepInputQuestions(answers)`가 **규칙으로** 고른다. AI가 질문을 만들지 않는다.

```
① 관계 경험에서 '가장 힘들었던 순간'으로 고른 축      (가장 강한 신호)
② 관계 경험에서 '중요했던 요소'로 고른 축
③ Declared에서 극단값(4~5 또는 1~2)으로 답한 축
④ 그 외 답한 축                                      (①~③이 비어도 최소 1개는 나온다)
```

- 같은 축에서는 pool의 첫 질문부터 쓴다.
- **무작위가 아니다** — 같은 입력이면 같은 질문이 나온다(사용자가 알아볼 수 있고, 테스트로 고정할 수 있다).
- 이미 답한 질문은 다시 고르지 않는다. 두 번째로 열면 다음 질문이 나온다.
- 더 고를 게 없으면 화면을 세우지 않고 바로 다음으로 보낸다.

관심 없다고 답한 축을 더 캐묻지 않는 것이 핵심이다 — 그건 질문을 늘리는 것이지 해상도를 올리는 게 아니다.

## 4. Evidence type

저장 형태(`SessionAnswers.deepInputs`):

```ts
{ axis: MirrorAxisKey, questionId: string, optionId: string }
```

각 보기는 **조건 문장 조각**(`condition`)을 하나씩 들고 있다.

```
'답장 간격이 길어지는 것'  →  condition: '답장 간격이 길어질 때'
'잘 모르겠어'              →  condition: ''   ← 근거가 되지 않는다
```

⚠️ `condition`은 **상황**이다. 감정·원인·성향이 아니다.
`불안한 편`(❌) / `답장 간격이 길어질 때`(⭕)

## 5. Downstream use — 어디에 쓰나

| 쓰는 곳 | 어떻게 | 결정론? |
|---|---|---|
| Compatibility 축 카드 | `네가 알려준 조건 · 답장 간격이 길어질 때` 한 줄 | **예** |
| AI 인용 허용 근거 | 그 축에만 `{source:'deep', field: axis}` 추가 | 예 |
| AI 입력 context | `deepConditions: [{axis, condition}]` | 예 |
| 근거 라벨 | `더 자세히 답한 것` (`추가 질문`과 다른 라벨) | 예 |

**결정론 경로를 반드시 하나 둔다.** AI 설명은 demo · 실패 · Quality Gate 어디서든
사라질 수 있어서, 그것만으로는 '답한 만큼 결과가 달라진다'를 보장할 수 없다.

축이 일치할 때만 쓴다 — 연락에 대해 좁혀준 조건을 갈등 카드의 근거로 쓰면
'사용자가 말한 것'이 아니라 '우리가 옮겨 붙인 것'이 된다.

## 6. 점수 영향 — **없다**

```
동기화율   declared × target 만 본다. deepInputs를 읽지 않는다
Mirror     declared × experience × currentRelationship 만 본다
Top 3      crossSourceInsights 선정 규칙 그대로
```

브라우저 실측 A/B: 같은 세션에서 심화 2문항만 답했을 때 **73 → 73**,
Mirror 축 판정·Premium 근거 선정 동일. 달라진 것은 `연락 방식` 카드에
`네가 알려준 조건 · 답장 간격이 길어질 때` 한 줄이 생긴 것뿐이다.

⚠️ **이 제약이 이 기능의 핵심이다.** 심화 입력이 점수를 움직이면 '더 많이 답한 사람이
더 높은 점수'가 되고, 그건 관찰이 아니라 설문 보상이다. 화면도 그 사실을 직접 말한다
(`여기 답은 동기화율 점수에 들어가지 않아`) — 답을 유도하지 않기 위해서다.

## 7. 이름이 비슷한 다른 것들

```
DEEP_QUESTION_BANK (data/deepQuestions.ts)  결제한 사용자에게 Premium 리포트가 묻는 질문
ADAPTIVE_FOLLOWUP  (data/adaptive.ts)       모순 후보 축에서 시스템이 먼저 묻는 1개
이 문서            (data/relationshipDeepInput.ts)  사용자가 직접 열어서 답하는 최대 2개
```

셋 다 'AI가 생성하지 않고 미리 검토한 pool에서 고른다'는 규칙을 공유한다.
저장 위치도 다르다(`deepAnswers` / `experience.adaptive` / `deepInputs`).

---

## 8. 질문 pool을 늘리려면

축마다 2개까지만 둔다. 늘리기 전에 이 질문에 답할 수 있어야 한다:

> **이 질문이 결과의 어느 문장을 더 구체적으로 만드는가?**

답할 수 없으면 그 질문은 없어도 된다. 그리고 새 보기에는 반드시 `condition`을 붙인다 —
조건이 없는 보기는 저장은 되지만 결과를 바꾸지 않으므로, 사용자에게 답한 보람이 없다.
