#### BLOCKER-02 — 사진이 사실상 Premium 진입 조건이었다 (수정함)

| | |
|---|---|
| Observed | 사진 없이 declared 5 · 관계경험 3 · 상대 4/4 · 심화입력 2 · 사건 1 · MBTI 양쪽 · 생년월일 양쪽을 다 채워도 `hasPremiumEvidence=false` → `정밀 분석을 위해 몇 가지 정보가 더 필요해` (Chapter 0개). **렌즈는 3/3 열려 있었고 action도 3개 있었다.** 사진 관찰이 있는 세션에서는 정상적으로 열렸다 |

#### 원인

두 경로가 **같은 Mirror insight 하나** 때문에 동시에 닫혔다.

```
Self-only 경로 : mirror.insights.length === 0  → Mirror가 1개라도 나오면 세션 전체 제외
cross 경로     : Mirror에서 파생된 insight → isFreeDuplicate가 제거
⇒ Chapter 0개 ⇒ hasPremiumEvidence = false
```

빠져나가는 현실적인 방법이 `observed`(사진) source를 더해 **Mirror에서 파생되지 않은**
연결을 만드는 것뿐이었다. 그래서 사진이 없는 사용자는 다른 근거를 아무리 채워도 막혔다.

실측(`/api/dev/premium-test`, 사진 없음):

```
insight 1개 : cs_mirror_contact | sources=[declared, relationship] | refs=2
→ sources>=2 · refs>=2 는 통과하지만 isFreeDuplicate에서 제거
→ mirrorInsightCount=1 이라 Self-only 경로도 차단
⇒ eligible=false · chapters=0   (lenses 3/3 · actions 3 인데도)
```

#### 수정

제외 단위를 **세션 → 축**으로 바꿨다(`selfOnlyAxes`).

```
before : mirror.insights.length === 0 && 답한 declared 축 >= 3
after  : (답한 declared 축 − 무료 Mirror가 보여준 축) >= 3
```

무료가 이미 보여준 것은 '세션'이 아니라 **그 축**이다. 그래서 그 축만 빼고 남은 축으로
판단한다 — 재판매 방지 원칙은 약해지지 않고 **더 정확해진다.** 위 실측 세션이면 Mirror가
연락 하나를 보여줬으므로 갈등 · 개인시간 · 애정표현 · 취미 4개가 남고, 이건 무료에서 한
번도 보여준 적 없는 축들이다.

⚠️ `hasPremiumEvidence`와 `canBuildSelfOnly`가 **같은 `selfOnlyAxes`를 쓴다.** 두 곳에
따로 적으면 '결제는 되는데 리포트는 비어 있는' 상태가 다시 생긴다.
⚠️ 충분성 가드(≥3축)는 그대로다. 게이트를 무력화한 변경이 아니다.

### POLISH-02 — `/ut` 콘솔의 `AI 모드` 표시가 서버 모드와 어긋남

콘솔은 `NEXT_PUBLIC_AI_MODE`만 읽는다(`AI_MODE_HINT`). 지금처럼 `AI_MODE=demo` ·
`NEXT_PUBLIC_AI_MODE=real`이면 콘솔은 `real`이라고 표시하지만 서버는 demo다.
참가자 화면 문제가 아니라 **운영자 도구 표시** 문제라 RC 범위 밖으로 둔다.
→ 대신 pre-flight 절차에서 `/api/dev/ai-guard`로 **서버 값**을 확인하도록 했다(§6).

### 이번에 손대지 않기로 한 것

`결과가 길어 보임` · `Lovy를 더` · `질문 더` · `색상/카드 크기` · `Premium 내용 추가` ·
`History 기능` · `전국 성향 %` · `복수 관계 cloud 저장` · `새 공유 방식`
→ 전부 2차 UT 이후 판단.

## 6. 참가자 시작 전 절차 (운영자)

기존 `/ut` 운영자 콘솔을 그대로 쓴다. **새 reset 기능을 만들지 않았다.**

```
1. /ut 열기
2. 'UT 결과 내보내기'로 직전 참가자 데이터 저장
3. '다음 참가자 준비 (초기화)' → 확인 모달에서 '초기화'
   → lym.* 저장값 삭제 + /onboarding으로 이동 (검증함)
4. 점검 패널에서 UT READY 확인
   - Premium CTA · Paywall 노출 ✓
   - 실제 결제 불가 ✓
   - 참가자 화면에 개발 도구 없음 ✓   (preview 배포는 NEXT_PUBLIC_AI_DEBUG=false)
5. 서버 AI 모드는 콘솔이 아니라 /api/dev/ai-guard 로 확인 (POLISH-02)
   → {"realProviderCalls":0,"envMode":"demo"}
```

⚠️ **사진은 준비시키지 않는다.** 사진은 optional 입력이고, BLOCKER-02 수정 이후
사진 없이도 Premium이 열린다. 사진 없는 자연스러운 흐름은 2차 UT에서 **반드시 허용**한다
— 1차 참가자 2명 모두 기기에 사진이 없었으므로 그게 오히려 기본 경로에 가깝다.
사진 분석(H3)을 관측하고 싶은 참가자에게만 **권장** 수준으로 안내한다.

초기화가 지우는 것: 참가자 답변 · 관계 기록 · Premium unlock · 심화 입력 · 사진 관찰 ·
사건 · UT 응답 · AI 캐시. 남기는 것: `lym.ut-mode.v1` · `lym.cloudLinks.v1`.
Supabase 저장 데이터는 건드리지 않는다.
