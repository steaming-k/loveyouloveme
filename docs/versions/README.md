# 문서 버전 보관소

이 폴더에는 **확정된 과거 버전 문서**가 동결 상태로 보관된다.

| | 위치 |
|---|---|
| **현재 기능명세서** | [`../기능명세서.md`](../기능명세서.md) — **v1.7** |
| **현재 기획서** | [`../럽유럽미_기획서_v1.md`](../럽유럽미_기획서_v1.md) — **v1.7** |
| 과거 버전 | 이 폴더 |

> ⚠️ **이 폴더의 파일은 수정하지 않는다.**
> 각 파일은 그 버전이 확정된 시점의 git 커밋에서 **그대로 추출한 원본**이다.
> 내용을 고치면 '그 시점의 기록'이라는 의미가 사라진다.
> 고쳐야 할 내용을 발견하면 **현재 문서에서** 고친다.

> ⚠️ **과거 버전의 `현재`·`Future`·`아직`은 그 시점 기준이다.**
> 예: `기능명세서_v1.5.md`의 'AI는 데모 규칙이다'는 v1.5 시점에는 사실이었고,
> v1.6에서 실제 파이프라인이 붙으며 더 이상 사실이 아니다.
> 각 파일 맨 위 배너에 이 경고가 붙어 있다.

## 다음 버전을 낼 때 (v1.8 작업 시작 시)

버전 문서는 **현재 문서 하나를 계속 고치고, 확정된 버전만 여기로 복사**하는 방식이다.
현재 문서와 이 폴더에 같은 내용이 중복되지 않게 하려는 것이다.

1. v1.7이 확정된 커밋 해시를 확인한다 → `61b59ce`
2. 그 커밋에서 두 문서를 추출해 이 폴더에 동결한다

```bash
git show 61b59ce:docs/기능명세서.md > docs/versions/기능명세서_v1.7.md
git show 61b59ce:docs/럽유럽미_기획서_v1.md > docs/versions/기획서_v1.7.md
```

3. 각 파일 맨 위에 동결 배너를 붙인다 (다른 파일의 배너를 복사해 버전·커밋만 교체)
4. 이 README의 표에서 v1.7 행의 *(현재 문서)*를 파일 링크로 바꾸고, v1.8 행을 추가한다
5. 현재 문서의 `문서 버전`·`제품 버전`을 v1.8로 올린다

> **부록 A 변경 이력은 현재 문서에 계속 누적한다.**
> 이 폴더는 '그때의 문서 전문'을 보관하고, 현재 문서의 부록 A는 '버전 간 무엇이 바뀌었는지'를
> 한눈에 보여준다. 두 역할이 다르므로 둘 다 유지한다.
