## 0. 표기 규칙

- **WF ID** — 와이어프레임 화면 번호 (`S01`~`S29`, `E1`~`E4`, `F1`~`F2`, `SH1`~`SH2`, `X1`)
- **Route** — 브라우저 주소 (`src/lib/routes.ts`의 `ROUTES` 상수)
- **파일** — 해당 화면의 실제 소스 경로 (`src/app/...`)
- **읽는 상태 / 쓰는 상태** — `SessionProvider`(`src/state/SessionProvider.tsx`)가 들고 있는
  `SessionAnswers`(`src/types/index.ts`) 중 이 화면이 참조·갱신하는 필드
- **그룹** — `Core`(필수 흐름) · `Key`(핵심 Product Moment, §50 7대 화면) · `Edge`(예외 상태) ·
  `Future`(후속 버전 컨셉) · `Share`(공유 카드) · `Add-on`(보조 기능)
- 모든 화면은 `ScreenLayout`(`src/components/common/ScreenLayout.tsx`)의 **header / scroll body /
  sticky footer** 3단 골격을 공유한다. 화면별 설명에서는 이 골격 위에 얹히는 내용만 다룬다.

## 1. 전체 사용자 흐름 (Funnel)

```
새로운 사람에 대한 궁금증
  ↓ S01 스플래시 → S02~S04 온보딩
S05 관계 상태 선택
  ↓
S06~S18  AI Profile Building (Observed → Declared → Relationship → Relationship Profile)
  ↓
S19 상대 정보 입력
  ↓
S20~S25  Compatibility (동기화율 → 근거 → 잘 맞는 신호 → 관찰 필요 신호 → 대화 질문)
  ↓
S26 Mirror Teaser  ◀── Primary KPI 전환점 (relationship_mirror_entry_click / compatibility_complete)
  ↓
S27 Relationship Mirror → S28 Core Insight
  ↓
S29 분석 후 홈  ◀── MVP 종료 지점
  ↓ (Future)
F1~F2 Relationship History
```

**제품 원칙 (design-guide.md §5, §10 반영):** 궁합 점수는 입구이고 결론이 아니다. 화면 정보
위계는 `Relationship Mirror > Compatibility Reason/Evidence > AI Profile Building > Compatibility
Score > Lovy Character` 순이며, 이 순서는 §6의 화면별 시각적 강도에도 그대로 반영돼 있다
(Compatibility Hero의 `78`은 브랜드 컬러 하나로만 강조되는 반면, Relationship Mirror는
레이더 차트 + 항목별 대조 5개 + Teaser 예고 화면까지 붙는다).

## 3. 공통 규칙 (전역 사양)

### 3.1 레이아웃 골격 — `ScreenLayout`

모든 화면은 세 영역으로 고정된다.

| 영역 | 규칙 |
|---|---|
| Header (flex-none) | `ScreenHeader` — 뒤로가기(←) · progress bar(선택) · 카운터(`질문 1/4` 등) · 오른쪽 액션(공유/수정 등) |
| Body (flex-1, scroll) | 좌우 여백 20px(`px-gutter`) 고정. `centered` 옵션이면 세로 중앙 정렬(스플래시·로딩·Empty·Error) |
| Footer (flex-none, sticky) | Primary CTA + 보조 액션. 하단 safe-area 26px(`pb-safe`) 항상 확보 |

뒤로가기는 `router.back()` 또는 명시적 `backHref`를 쓴다. **Declared/Past 단계는 모두
`backHref`를 이전 스텝으로 명시**해 브라우저 히스토리가 꼬여도 항상 올바른 이전 화면으로
돌아간다.

### 3.2 진행률(Progress) 표시

상단 progress bar는 **AI Profile Building 전 구간(S05~S19)에서 하나로 이어진다.** 각 화면이
표시하는 진행률(%)은 다음과 같다 (`ScreenHeader`의 `progress` prop).

| 화면 | 진행률 |
|---|---|
| S05 관계 상태 | 8% |
| S06 프로필 인트로 | 14% |
| S07 사진 입력 | 22% |
| S09 Observed 결과 | 30% |
| S10 Declared 1 | 36% |
| S11 Declared 2 | 42% |
| S12 Declared 3 | 48% |
| S13 Declared 4 | 54% |
| S14 과거 관계 인트로 | 60% |
| S15 과거 관계 Q1 | 66% |
| S16 과거 관계 Q2 | 72% |
| S17 과거 관계 Q3 | 78% |
| S19 상대 정보 입력 | 88% |

S18(Relationship Profile), S21 이후(Compatibility·Mirror)는 별도 progress bar 없이
`title`/`centerLabel`만 쓴다 — 이 구간부터는 "진행 중인 설문"이 아니라 "결과를 보는 흐름"이기
때문이다.

### 3.3 검증 / 에러 처리 정책

`alert()`를 쓰지 않는다. 상황에 맞춰 4가지 패턴만 쓴다.

| 패턴 | 컴포넌트 | 쓰는 곳 |
|---|---|---|
| 인라인 에러 | `InlineError` (`primitives.tsx`) | 필수 입력 누락 시 CTA 위에 노출 |
| 토스트 | `ToastProvider` / `useToast()` | 저장·제외·복사 등 짧은 확인 메시지 (2.4초 자동 소멸) |
| 바텀시트 | `BottomSheet` | AI 결과 수정, Core Insight 수정 |
| 확인 모달 | `ConfirmModal` | 되돌리기 어려운 동작(분석 제외) 확인 |

### 3.4 데이터 영속성

- 세션 답변: `localStorage['lym.session.v1']` — `SessionProvider`가 마운트 시 복원, 변경마다 저장
- 분석 이벤트 로그: `localStorage['lym.analytics.v1']`
- 업로드 사진의 `objectUrl`은 새로고침 시 무효화된다(의도된 동작 — 사진은 서버로 보내지 않고
  분석 후 저장하지 않는다는 프라이버시 원칙과 일치)
- `hydrated` 플래그가 `true`가 되기 전에는 계산 결과를 보여주지 않는다
  (`HydrationGate` — §3.7 참고)

### 3.5 로딩 시퀀스 공통 규칙 — `LovyLoading`

일반 스피너 하나로 끝내지 않는다. 러비의 관측 로그 4줄이 순서대로(줄당 1.1초) 쌓이고, 로그가
끝나면 자동으로 다음 화면으로 넘어간다. `prefers-reduced-motion`이면 로그를 한 번에 모두
보여주고 1.2초 뒤 넘어간다. 로딩에 실패하면(`?error=1`) 시퀀스 대신 E2 에러 화면을 보여준다.

### 3.6 접근성 공통 규칙

- 모든 선택 요소는 실제 `<input type="radio">` / `<input type="checkbox">` 기반(시각 스타일만
  커스텀)
- 최소 터치 타깃 44px(`min-h-11`)
- 아이콘 전용 버튼에 `aria-label`
- 게이지·상태 뱃지(MATCH/GAP/CHANGE, 잘맞음/관찰필요)는 색만으로 구분하지 않고 `sr-only` 텍스트
  또는 라벨을 함께 노출
- 토스트·로딩은 `role="status"`/`aria-live="polite"`, 에러는 `role="alert"`
- `prefers-reduced-motion: reduce` 시 모든 CSS keyframe 애니메이션 정지 (`globals.css` 전역 처리)

### 3.7 Hydration 안전장치 — `HydrationGate`

결과를 계산해서 보여주는 화면(`/compatibility`, `/mirror`, `/profile/result`)은
`HydrationGate`로 감싼다. `localStorage` 복원이 끝나기 전에 렌더하면 "답변이 하나도 없는
상태"로 계산된 빈 결과가 한 프레임 스쳐 보이기 때문에, 복원 전에는 짧은 로딩 표시만 하고
복원 후에 실제 결과를 렌더한다.

### 3.8 러비(Lovy) 사용 규칙

| 크기 | 쓰는 곳 |
|---|---|
| 96~200px | Splash, Onboarding, 로딩, Empty/Error, Mirror Teaser |
| 46~70px | 결과 화면의 코멘트 말풍선 (`LovyMessage`) |
| 38~46px | 일반 입력 화면의 아바타 |

역할은 **관찰자**다. `docs/design-guide.md` §1의 대표 카피 규칙(단정하지 않기, 확신 없으면
숨기지 않기)을 모든 `LOVY_LINES`/`STATE_COPY` 문구가 따른다.

## 6. 핵심 계산 로직 상세

> ⚠️ **아래 로직은 심리 검사나 과학적 진단이 아니다.** 입력값의 공통점·차이를 사용자가 직관적으로
> 읽을 수 있게 만든 **규칙 기반 데모 로직**이며, 실제 AI 백엔드가 붙으면 `src/services/aiService.ts`
> 구현만 교체하면 된다. 코드에도 동일한 경고 주석이 붙어 있다(`src/lib/logic/*.ts`).

### 6.1 동기화율 (`src/lib/logic/compatibility.ts`)

**1단계 — 값 정규화** (`src/lib/logic/values.ts`)

| 축 | 나의 값 출처 |
|---|---|
| `talk`(대화 방식) | 고정값 `4`(사진 관찰) |
| `rhythm`(생활 리듬) | 고정값 `3`(사진 관찰) |
| `alone`(개인 시간) | `declared.alone` (1~5) |
| `affection`(애정 표현) | `AFFECTION_VALUE[declared.affection]` — a1=1, a2=3, a3=5 |
| `conflict`(갈등 해결) | `CONFLICT_VALUE[declared.conflict]` — now=5, soon=3, space=1 |
| `contact`(연락 방식) | `declared.contact` (1~5) |

상대 값은 `TARGET_LEVEL_VALUE` — l=1, m=3, h=5, x(모름)=`null`(비교 제외).

**2단계 — 축별 정렬도**

```
alignment = max(0, 5 - |나의 값 - 상대의 값|)
```

`alignment >= 4` → **잘 맞는 신호**, `alignment <= 2` → **관찰이 필요한 신호**, 그 외 → 중립.
어느 한쪽이라도 `null`이면 `alignment = null`(비교 불가, `unknownLabels`에 축 라벨 추가).

**3단계 — 총점**

```
비교 가능한 축이 3개(TARGET_MIN_KNOWN) 미만이면 → score = null (E3)
그 외:
  sum = Σ alignment (비교 가능한 축만)
  score = 40(SCORE_FLOOR) + floor((sum / (비교 축 수 × 5)) × 52(SCORE_RANGE))
```

점수 하한을 40으로 둔 이유: 6개 축 중 일부만 달라도 '0점'처럼 읽히면 사용자가 관계를
단정적으로 해석하게 되기 때문. 점수 범위는 실질적으로 **40~92**.

**확신도(`confidence`)**

```
comparedCount >= totalCount - 1  →  high
comparedCount >= TARGET_MIN_KNOWN(3)  →  medium
그 외  →  low
```

### 6.2 Relationship Mirror 판정 (`src/lib/logic/mirror.ts`)

**Declared Me 값** — `alone`/`contact`은 원값, `hobby`=`HOBBY_VALUE`(h1=1,h2=3,h3=5),
`conflict`=`CONFLICT_VALUE`, `affection`=`AFFECTION_VALUE`. 미응답이면 중립값 `3`으로 대체
(Mirror가 완전히 비어 보이지 않도록).

**Relationship Me 값 (역산 규칙)** — `toRelationshipMirrorValues()`

| 축 | 값 |
|---|---|
| `alone` | `important`에 `'alone'` 포함 시 `5`, 아니면 `4` |
| `contact` | `hardest === 'contact_drop'`이면 `5`, `important`에 `'contact'` 포함 시 `4`, 아니면 `2` |
| `hobby` | `important`에 `'hobby'` 포함 시 `4`, 아니면 `2` |
| `conflict` | `important`에 `'conflict'` 포함 또는 `hardest === 'fight_silence'`면 `5`, 아니면 `3` |
| `affection` | `important`에 `'affection'` 포함 시 `4`, 아니면 `3` |

**상태 판정**

```
diff = 관계 속 값 - 말한 값
|diff| <= 1        → MATCH    (말한 기준과 관계에서의 반응이 비슷)
diff >= 2          → GAP      (중요하지 않다고 했지만 관계에서 더 크게 반응)
diff <= -2         → CHANGE   (중요하다고 했지만 경험 후 우선순위가 내려감)
```

**Teaser / Core Insight 축 선정** — GAP 상태 축이 하나 이상이면 그중 첫 번째, 없으면
`|diff|`가 가장 큰 축. `contact` 축이 GAP으로 선정되면 헤드라인은 고정 문구(§7.4)를 쓰고,
그 외에는 `"너는 {label}에서 말한 기준보다 실제 관계에서 더 크게 반응하는 사람일지도 몰라."`
템플릿을 쓴다.

### 6.3 Observed Me 관찰 규칙 (`src/lib/logic/observed.ts`)

```
사진 3장 미만  → 관찰 없음(Empty)
사진 3~4장     → confidence='low' 항목 제외하고 노출
사진 5장 이상  → 4개 항목 전부 노출
```

### 6.4 Relationship Profile 확신도 (`src/lib/logic/profile.ts`)

```
experience.skipped === true                                    → low
!(important.length >= 3 && selfGap !== null)                    → low
note(서술)가 비어있지 않음                                        → high
그 외                                                            → medium
```
